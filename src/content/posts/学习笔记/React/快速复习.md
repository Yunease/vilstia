# 快速入门

## 理解嵌套组件的概念

React 应用程序是由 **组件** 组成的。一个组件是UI，也就是用户界面的一部分，它拥有自己的逻辑和外观，组件可以很小，也可以很多，但最重要的地方是一次编写到处复用，可以减少一些工作量。

React 组件是返回标签的 JavaScript 函数，其实和 JSX 本质也一样：

```react
function MyButton()
{
	return(
		<button>按钮</button>
	)
}
```

于是，现在就声明了 `MyButton` ，现在把它嵌套在另一个组件中：

```react
export default function MyApp(){
	return (
		<div>
			<h1>这是我的应用<h1>
			<MyButton />
		</div>
	)
}
```

对了，HTML 标签必须是小写字母，而 React 必须以大写字母开头，而且命名规则并不遵循大小驼峰。可以靠这个特征区分 React 组件和 HTML 的区别。

`export default` 关键字指定了文件中的主要组件。



# 快速理解 JSX

上面这种写在 JavaScript 中的 HTML 元素，被称为 JSX 语法，虽然也可以不用这种方法，但是大多数 React 项目都会使用 JSX 。JSX 比 HTML 要严格一些，你必须正确闭合标签。也不能直接返回多个 JSX 标签，必须放在一个共享父级（比如常见的 <div>……</div>，< >……< >）

比如：

```jsx
function AboutPage() {
  return (
    <>
      <h1>关于</h1>
      <p>你好。<br />最近怎么样？</p>
    </>
  );
}
```

如果想把很多 HTML 转换为 JSX，可以使用一些批处理工具，而不需要反复手动编写。



# 添加样式

在 React 中，可以使用 `className` 来指定一个 css 的class。这里有点不太一样，简单记忆一下：

在 React 中，className = HTML 的 class

它的工作方式和 HTML 的 `class` 属性的工作方式相同，不需要额外的理解负担，比如：

```react
<img className="avatar" />
```

最终渲染在网页上，它等效于：

```html
<img class="avatar" />
```

你可以在一个单独的 css 文件中为它编写 css 规则，当然，我们后续还会介绍 Tailwind CSS，这里先省略了。



# 显示数据

JSX 会让你把标签放到 Javascript 中，而大括号会让人你回到 Javascript 里，这样就可以从代码中嵌入一些变量给用户了，例如：

```jsx
return (
	<h1>
		{user.name}
	</h1>
)
```

你还可以将 JSX 属性 “转义到 JavaScript”，但你必须使用大括号 **而非** 引号。例如，`className="avatar"` 是将 `"avatar"` 字符串传递给 `className`，作为 CSS 的 class。但 `src={user.imageUrl}` 会读取 JavaScript 的 `user.imageUrl` 变量，然后将该值作为 `src` 属性传递：

```react
return (
  <img
    className="avatar"
    src={user.imageUrl}
  />
);
```

有时候会看到一个令人费解的语法，但它并不困难，我们一起来看看吧。

```react
style={{}}
```

这里内测的大括号，其实是一个普通的js对象。



# 条件渲染

React 没有特殊的语法来编写条件语句，因此你使用的就是普通的js代码，这一点有点类似于微信小程序中的if条件渲染。例如：

```react
let content;
if (isLoggedIn) {
  content = <AdminPanel />;
} else {
  content = <LoginForm />;
}
return (
  <div>
    {content}
  </div>
);
```

条件运算符等等，就暂时不展开了，我觉得应该没人会为了省几行代码这么写。



# 渲染列表

可以使用 for 循环 和 array 的 map() 函数来渲染组件列表。

假设有一个产品数组：

```react
const products = [
  { title: 'Cabbage', id: 1 },
  { title: 'Garlic', id: 2 },
  { title: 'Apple', id: 3 },
];
```

在你的组件中，使用 `map()` 函数将这个数组转换为 `<li>` 标签构成的列表:

```react
const listItems = products.map(product =>
  <li key={product.id}>
    {product.title}
  </li>
);

return (
  <ul>{listItems}</ul>
);
```



# 响应事件

思路和js其实差不多，这里简单说说就ok了。

```react
function MyButton() {
  function handleClick() {
    alert('You clicked me!');
  }

  return (
    <button onClick={handleClick}>
      点我
    </button>
  );
}
```

当按钮被点击的时候，就会调用alert弹窗。



# Hook

以 ues 开头的函数被称为 Hook，让我们看看 gemini 是如何解释它的：

> 简单来说，**React Hook 是 React 16.8 引入的一套函数式 API**。它允许你在不编写 `Class`（类组件）的情况下，在函数组件中使用状态（State）、生命周期以及其他的 React 特性。
>
> 在 Hook 诞生之前，函数组件只能充当“无状态的展示型组件”（Stateless Functional Components）；想要管理组件内部数据或处理网络请求，必须写冗长繁琐的 Class 组件。Hook 的出现彻底颠覆了 React 的开发范式。

Hook 的命名约定统一以 `use` 开头。最基础、使用频率最高的核心 Hook 有：

`useState`：局部状态管理：让函数组件拥有持久化的内部状态。

```react
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      点击了 {count} 次
    </button>
  );
}
```

#### 其他高频 Hook

- **`useContext`**：跨层级直接读取 Context 上下文数据，免去逐层 `props` 传递的麻烦。
- **`useRef`**：用来持久保存一个与渲染无关的变量，或者直接获取真实的 DOM 节点引用。
- **`useMemo` & `useCallback`**：性能优化双子星，分别用于缓存复杂计算的“计算结果”和“函数引用”，避免子组件不必要的重复渲染。
- **`useReducer`**：适合管理复杂状态逻辑（类似于轻量级的 Redux 模式）。

当然，你也可以自定义 Hook，你可以把相关的状态逻辑抽取成一个普通的 JavaScript 函数（以 `use` 开头），在其中自由调用内置 Hook。

Hook 的两条硬性规则：

React 底层是按**调用顺序**来追踪 Hook 对应的数据的，因此必须严格遵守以下规则：

1. **只能在最顶层调用 Hook：** 不能在循环语句、条件分支（`if`）或嵌套函数中调用 Hook，确保每次组件渲染时，Hook 的执行顺序完全一致。
2. **只能在 React 函数中调用 Hook：** 只能在 React 函数组件内或自定义 Hook（`useXxx`）内部调用，不能在普通的普通工具函数或类组件中调用。
