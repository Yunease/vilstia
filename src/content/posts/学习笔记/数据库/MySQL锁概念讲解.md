# MySQL 锁的全景视图

mysql 的锁很多，比如：

- 全局锁
- 表级锁
- 行级锁
- 共享锁
- 排他锁
- 意向锁
- 记录锁
- 间隙锁
- 临键锁
- 插入意向锁
- 悲观锁
- 乐观锁
- MVCC
- 幻读
- 死锁



# 锁的粒度：从大到小

假如一栋仓库里有一个东西要上锁，可以直接锁住仓库，也可以锁住物品所在的区域，也可以只锁住装有物品的抽屉。锁拥有大小，分为：

- 全局锁
  - 锁住整个库
  - 场景：全库备份
  - 命令： `FTWRL`
  - 锁住后，其他人只能读，但不能更写。
- 表锁
  - 锁住整张表
  - 特点：开销小，并发低
  - 引擎：MyISAM
  - 缺点：一个人锁住，其他人只能等待。
- 行锁
  - 锁住单行数据
  - 特点：并发高，可能死锁
  - 引擎：InnoDB
  - 缺点：开销较大



# 用锁的两种模式：乐观锁和悲观锁

- 悲观锁：
  - 主要观点：世界充满危险，任何数据都应该先保护锁上再说
  - 适用于多写少读的情景
- 乐观锁：
  - 主要观点：世界很美好，冲突只是偶尔的事
  - 先操作，提交时再进行验证
  - 适用于多读少写的场景



# 按照属性分类：共享锁和排他锁

- 共享锁（S锁（ share ） / 读锁）
  - 我读的时候，你也可以读
  - 多个事务可以同时读取同一种资源
  - 读读共享，读写互斥
- 排他锁（X锁 / 写锁）
  - 我写的时候，谁也不许动
  - 独占资源，其他事务无法进行，无法读写
  - 写写互斥，读写也互斥



# 特殊所

一个特殊的锁：意向锁

主要观点：我接下来会对这个行进行处理，提前告诉整个表，注意！

本质：表级锁，但服务于行锁

作用：当事务想加表锁时，无需遍历所有行，秩序检查意向锁，极大程度提升效率

机制：当事务获取行锁时，InnoDB自动加上意向锁。

分类：也分为共享意向锁和排他意向锁



记录锁：精准锁定，只锁一行

特点：只锁一个，但是很多时候不可能，因为查询结果是一个范围。



为了解决幻读，InnoDB增加了两种新的特殊锁：

- 间隙锁
  - 锁定一个开区间，不锁记录本身，防止间隙中插入新的数据
- 临键锁
  - 记录锁和间隙锁的结合，锁定一个左开右闭的区间。
- 核心目的：防止幻读

> **幻读（Phantom Read）**是指在同一个事务中，先后两次执行相同的范围查询时，因为另一个并发事务插入（INSERT）或删除（DELETE）了满足该条件的记录并提交，导致后一次查询看到了前一次没有看到的行（如同凭空出现的“幽灵”数据），或者发现行数发生了变化。
