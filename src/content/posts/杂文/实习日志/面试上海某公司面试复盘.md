# 起因

昨天朋友推荐我去一家公司面试试试水，搞得很神秘，只说是全栈 Agent 岗位，具体细节没说，这可惨了，我不知道该怎么复习，问了一下对接的人，人家说要问我的 Github 主页，并让我仔细看看自己的简历，然后就什么也没说了，这我也没招，干脆躺平随缘面对了。



# 面试流程

接下来说说面试题和复盘。

一上来先是自我介绍，简单介绍了学校，日常做的方向。然后对方问了一句没有了吗？我觉得这是一个信号，可能还想听一些自我介绍，下次面试可以观察对方是否时间紧张，考虑可以多说一点。比如说一下自己最近的项目，求职规划路线什么的。

然后简单问了一下我对于新兴技术的敏感性，问了我是什么渠道获得的这些信息，我主要提出了三个：

- 我在做短视频积累个人 IP，组建了一个粉丝群，每天有人分享消息。
- 程序员，技术相关的论坛网站。
- 刷一些社交媒体关注一些 AI 资讯的账号。

接下来问为什么选择这个岗位，看我简历有游戏开发的落地经验，为什么要来 Agent 智能体开发这边？

简单说了一下对 AI Agent 行业的整体认可，并说一下垂直 Agent 的市场前景，游戏更多的是个人爱好。

接下来就是问我的个人项目，[Vilstia](https://github.com/Yunease/vilstia)，[Ghost Cat Agent(Sharin)](https://github.com/Yunease/ghostcat)，[MintWord](https://github.com/XiaFoundry/MintWord)都问了，简单说一下每个问题问了什么。

Vilstia：

```json
面试官：嗯，这是你的个人网站吗？
我：是的，这是用 Astro 框架搭建的个人静态网站。
面试官：你是怎么部署的，是部署在 Github.io 上的吗？
我：不是，我主要部署在 CloudFlare 上，其他平台如 Github.io,Vercel,Netlify 等也做了部署，但是综合额度考虑之后选择了 CloudFlare，主要是因为静态的 Pages 是无限 CDN 的，而且构建也很宽松，基本上用不完，其他平台虽然也有免费额度，但整体没有这么多，另一方面部分 Key 需要存后端，用 CloudFlare Worker 可以直接解决这个问题，不需要额外部署云服务器。
面试官：你还做了 SEO，遇到的最大困难是什么，你怎么证明你的 SEO 有效？
我：最大的困难是为了页面加载优化的时候处理的性能问题，这个项目存在一个重大缺陷，所有 CSS 都挂在一个 image 加载器上，如果为了性能把他优化掉，样式就会全部崩坏。后来对这个问题做了局部重构，性能上去了，网站的权重也高了，这是我建站最严重的问题，现在已经解决。证明 SEO 和 GEO 最有效的方法就是看数据，（打开 umami 和 DeepSeek 当场问了一下），初期异常流量的来源是谷歌收录的爬虫，后面随着爆款文章呈现波动态势，整体数据非常健康。
```

Ghost Cat：

```json
面试官：我看到你做了一个 Agent，你的这个 Agent 和市面上的 Agent 有什么差异吗？你做了哪些调整？
我：这个 Agent 要和 Moss VMina 这个项目结合起来（现场演示了 Moss VMina 和 Open AI 兼容接口），这个 Agent 主要做了对小模型的调优，我发现小模型接入主流 Coding Agent 表现不佳，排查的时候发现主要卡在了 Tolls Calling 的过程，因为小模型一次吃不下这么多上下文，注意力容易被稀释，最终卡在报错循环直到超时重试。我做的优化是大幅度缩减了报错，对上下文采用了比较激进的压缩策略，同时要求工具调用的时候只发工具名，模型选择工具后才会发送少量工具信息，避免上下文被吃满。同时还对一些关键词做了语义化兼容，比如让模型写 Json 如果写错写成了中文括号无法闭环，Agent 会检测这种简单问题并修正。目前优化之后，模型可以完成简单的 Python 代码编写，但更多的是辅助完成文档编辑。
面试官：你的这个 Moss VMina 训练集跑分是 75/100，这个数据怎么来的？包含什么维度？
我：这个测试集是我让 Chat GPT 生成的针对个人助手定位的小模型的测试集，包括一百道题，模型返回结果，最后让 Chat GPT 来对结果进行打分，打分只允许 0，0.5，1 ，75是最后的分数。主要包含身份理解，命令执行，日常对话，常识理解，短上下文记忆能力。
面试官：你有没有验证过没有训练的版本的跑分？你训练的结果会更好吗？
我：这不是一个严谨的学术任务，因此没有做过这个跑分，但是我可以肯定的是训练后的结果是一定跑分更高的，因为其中包含身份理解的任务，训练后的模型会稳定的表达自己是 Moss VMina 而非 Qwen，未训练的模型会全部丢分，而且 Chat GPT 比对过 Moss VMian 和底模，后训练的版本语气更自然，更贴合个人助手的定位。
面试官：TTS的过程你搭建了一个兼容 Open AI 的接口，这是怎么实现的？
我：这个部分是 AI 做的，我不太清楚细节，但技术栈是 Fast API，使用 Python 获取本地 Local host，然后暴露出一个 URL，一个 model name，一个 API key，就和日常调用 DeepSeek 一样，通过这种方式可以把模型接入其他 Agent 里。
面试官：你的模型是流式输出吗？TTS 模型呢？
我：模型是原生流式输出的，但是 TTS 不是，流式 TTS 输出是一个比较复杂的工程任务，涉及语义化切片，而且对于我选择的 GPT-Sovits 模型来说，流式 TTS 的效果并不好，最终改为了模型流式输出 + TTS 模型按符切分的输出方式。
```

MintWord：

```json
面试官：你这个项目是跨平台的，具体是怎么实现的？
我：我们在项目一开始就使用了 Tauri 这个跨平台的框架，除了少数内容需要针对特定平台微调，剩下的内容一次编写可以到处运行。
面试官：什么东西需要你针对性的微调？你怎么确定它能在多平台跑通？
我：比如一些微软或者苹果独有的功能需要单独适配，以项目来说，Windows TTS 是系统自带的，mac OS 则没有这个东西，需要专门做一个 mac OS 的版本，Linux 则可能需要一个单独的 TTS。mac OS 的版本是另一个合作者一起处理的，我测试了多个安装包，确保 Windows 和 Linux 上是可行的。
```

面到一半，突然又来了一个人，打断了面试，说是中途进来的，要问我一些问题，此人很有可能是老板，于是我调整心态，准备认真应对：

```json
对方：你平时会用什么 AI 工具，你都是怎么用的？
我：市面上基本上所有 AI 工具我都用过，主要取决于当前哪一家的模型最强，或者哪家的优惠力度不错，最近作为主力的 Agent 是谷歌的反重力和腾讯的 Workbuddy，之前也用过阿里的 Qoder。其他的 Agent，比如 OpenCode，PI，Claude Code，Codex，DeepSeek harness，Copilot，Cursor，Zcode之类的也都用过。
对方：25年以来，Agent 发展非常快，第一代 Agent 比如 Claude Code 使用的人很有限，然后龙虾智能体爆火，到现在有了新的 Agent，这些 Agent 之间，迭代的点主要是什么？
我：首先，Claude Code 对比过去直接调用 API 或者网页版对话，最重要的能力是拥有工具调用能力，甚至可以拿到一定电脑权限来执行 CLI 命令，用户不需要复制粘贴，AI 就可以自己阅读项目文件，针对性进行修改。龙虾则是重点提出了沙箱环境，Agent 循环和子 Agent 下发，可以在受限环境中执行可控命令。当然现在 Claude Code 也在一定程度上追加了这些功能。对于普通用户而言，还有一个很重要的区别是 Claude Code 是运行在 CLI 环境的 Agent，从龙虾开始就有 GUI 了，图形化界面对于普通用户来演非常重要，它的火爆在很大程度上和 GUI 有关。
对方：我对你的回答不是很满意，Claude Code 和 龙虾智能体之间的区别讲的不是很清楚，你还有什么补充的吗？
我：呃，我觉得还有个人化这方面，Agent 会通过历史对话，比如用一个 Memory 层来进行持久化记忆，在此之前 AI 完成一个任务是抽卡，很不可控，现在可以根据你的个人偏好做出个性化的回答等等。
对方：现在我要问一些名词，你了解 Prompt 工程，Skill，Mcp 分别是什么吗？
我：Prompt 工程，嗯，25年有很多论文研究发现一类特定的提示词可以让模型激活更强的能力，针对此有很多研究，比如角色扮演类型，鼓励类型和责罚类型，现在也产生了一些特定提示词可以增强模型的安全约束，等等，由此还衍生出了一些提示词破甲，提示词注入等网络安全层面的技术。Skills 本质上是一种稳定复现的工作流，但是和 Workflow 也有区别，后者是把整个过程封装在一起，前者则是把 Agent 处理任务需要的步骤和相关工具准备好，更灵活，而且可以面向不同的情况。Mcp 则是一种协议工具，可以让 AI 直接操控应用程序本身，这说起来有点抽象，举个例子，Unity 有很多中间二进制文件，通常来说 AI 是不能直接读取这种文件的，通过 MCP 可以用命令来操控 Unity，Unity 会直接把节点树，或者场景直接返回过去，不需要直接读写二进制文件。
对方：那这个 SKills 和直接把提示词复制进去，有什么区别吗？
我：嗯，首先头部的 Yaml 字段就不一样，这主要是用来注册的，可以在 Agent 内部快速读取 Skills。另外 Skills 除了提示词，还包括中间层工具和对应的源码。举个简单的例子，如果让 AI 做一个音量均衡批处理工作，Skills 内部应该包括三个部分，第一个部分是提示词，第二个部分是 ffmepg 的安装包，当环境内没有 ffmepg 的时候，AI 会自动安装它，第三个部分是音量均衡的 Python 脚本，AI 读取完毕后，可以安装环境，然后执行 Python 文件，就可以自动完成音量均衡的任务了。
对方：传统后端你了解多少？消息队列知道吗？
我：呃，我平时不太接触这些东西，不是很清楚。
对方：那么你接触过 Docker 吗？
我：Docker 是一种规范化的工具，呃，类似于把一些操作封装成一个容器，比如通过 Docker 在 Linux 安装一些云服务器之类的东西。但是我在 Windows 上不太用这个东西，不是很了解。
对方：我看你还做过安卓 APP，你有在安卓 APP 里增加 AI 服务吗？是怎么做的？
我：我做了一个简单的 AI chat 玩具，可以写角色设定，然后看这些角色之间的互动。不过这个东西没有认真深挖，只是简单用着用来玩的。
```

### Vilstia

**第一个问题：Cloudflare 的优势表达得不够严谨。**

你说静态 Pages 无限 CDN，这种表述容易被追问。更准确的表达应该是：Cloudflare Pages 提供了适合静态站点的全球边缘分发能力，在我的访问规模下，免费额度和部署体验已经足够，而且可以通过 Cloudflare Workers 或 Pages Functions 处理需要服务端执行的逻辑，减少额外服务器成本。

注意，不要把免费计划的资源额度说成无限。免费服务的具体额度和限制可能调整。

**第二个问题：你没有真正回答 SEO 效果如何证明。**

你说：

> 初期异常流量的来源是谷歌收录的爬虫，后面随着爆款文章呈现波动态势，整体数据非常健康。

这里有个逻辑问题：爬虫访问量不等于 SEO 成效，真正证明 SEO 效果的应该是：

| 指标                         | 说明                       |
| ---------------------------- | -------------------------- |
| Google Search Console 展示量 | 页面在搜索结果中出现的次数 |
| 搜索点击量                   | 用户通过搜索进入网站的次数 |
| CTR                          | 搜索结果点击率             |
| 平均排名                     | 关键词在搜索结果中的表现   |
| 自然搜索流量                 | 实际带来的访问             |
| 页面索引数量                 | 搜索引擎实际收录情况       |

而且你还提到了 GEO，GEO（Generative Engine Optimization）和传统 SEO 不能完全混为一谈。

如果要证明 GEO 效果，可以观察：

- AI 搜索平台带来的推荐访问。
- 内容被 AI 搜索引擎引用的情况。
- 特定问题下的品牌或网站提及情况。

DeepSeek 的访问来源可以作为一个信号，但不能单独证明 GEO 优化有效。

**建议：下一次面试，把网站的数据指标准备好。**

你的网站长期运营、有实际访问量，这是非常有价值的资产。不要浪费这个优势。



### Ghost Cat

我尤其喜欢你对小模型 Tool Calling 问题的描述。

你发现：

- 小模型处理复杂上下文时容易出现注意力分散。
- 工具调用信息过多会挤占上下文。

这不是单纯看了几篇 Agent 文章就能讲出来的东西，它来自实际使用和调试，而且你的优化方向是有合理性的，不过，我认为这里有三个问题。



#### **1. 你的评测体系不够严谨**

面试官问：

> 有没有验证过没有训练的版本的跑分？

这个问题问得非常好，你目前的测试体系有几个缺陷：

1. 测试集由 ChatGPT 生成，可能存在题目质量和覆盖面问题。
2. 使用 ChatGPT 作为评分者，存在评判偏差。
3. 训练集与测试集的独立性没有得到充分证明。
4. 没有底模对照实验。
5. 没有不同随机种子下的稳定性测试。

### **4. MCP：你的回答有一个重要的技术错误**

你说：

> MCP 可以让 AI 直接操控应用程序本身。

这句话不完全准确。MCP（Model Context Protocol）是一种标准化的客户端与服务端通信协议，它主要定义了三类能力：

- Tools：工具，模型可以通过客户端请求执行。
- Resources：资源，提供上下文数据。
- Prompts：可复用的提示模板。

你举的 Unity 例子是成立的，但真正执行操作的不是 MCP 协议本身，而是 **Unity MCP Server**，这里有个重要区别：MCP 不负责理解 Unity 的二进制文件，也不负责直接操作 Unity 内部，它提供的是一个标准化的能力调用接口，这一点如果面试官继续追问，你必须能讲清楚。

否则，面试官很容易认为你只是一个会使用 AI 生成代码的产品开发者，而企业招聘全栈 Agent 工程师，通常希望你有能力承担代码的维护责任。



## **2. 你的知识面比知识深度发展得快**

你接触过的东西真的很多。Astro、Tauri、FastAPI、Qwen、RAG、SFT、TTS、MCP、Skills、OpenClaw、各种 Coding Agent……但有些东西，你只是用过，还没有真正理解，这不是坏事，我甚至认为这与你的开发方式有很大关系：你习惯通过实际项目快速接触新技术。

不过现在应该调整学习方式：**每完成一个项目，都要抽出时间研究项目中最核心的三项技术，确保自己可以脱离 AI 独立解释其工作原理。**



## **3. 不要为了回答问题而编造答案**

你说遇到一个完全没听过的 Agent，最后随便编了一下。我建议以后不要这样做。其实有一个非常好用的回答方式：

> 这个技术我目前没有实际接触过，所以不敢直接给出准确的结论。不过从你刚才描述的定位来看，我猜测它主要解决的是……如果方便的话，能不能介绍一下它与目前主流 Agent 的区别？

这样做有几个好处：

- 不会因为错误信息失去可信度。
- 能展示你的技术推理能力。
- 能把问题转化成技术交流。
- 有机会获得面试官的真实评价。

尤其你现在的优势就是学习能力和技术敏感性，没有必要假装自己什么都懂。
